# 週次システム障害まとめ(2026-10-23〜10-29)

今週は、Google Cloudのロンドンリージョン障害の最終報告書が公開されたほか、日本では「au・UQ mobileのメール障害」「ドコモの音声通話障害」と、携帯キャリアの障害が続きました。先週から続くPHP脆弱性対応のサービス停止も、ようやく復旧が進んでいます。

> 注: web検索(12回上限)で確認できた情報のみを要約しています。時刻は特記がなければ日本時間(JST)です。

## 🌐 メガテック系

### 1. Google Cloud ロンドン(europe-west2)障害の最終報告(障害は10/20発生、報告は10/27公開)
- 発生: 10/20 7:00〜13:10(英国時間BST。約6時間)
- 対象: Google Cloud europe-west2リージョン(ロンドン)。Compute Engine(仮想マシン)、GKE(コンテナ基盤)、Cloud SQL、BigQueryなど多数。英国の銀行や配送会社などにも影響が出たと報じられた。
- 原因(Google公表): データセンターの外部電力ケーブル故障で電源が喪失。本来は非常用発電機が自動起動するはずが、制御装置(PLC＝設備を自動制御する小型コンピューター)の設定ミスで起動指令が出ず、UPS(無停電電源装置)のバッテリーが尽きて全停電に至った。保守作業中で電源系統が片系統だけだったことも重なった。
- 影響範囲: 主にゾーン(データセンター内の区画)europe-west2-b。ただし他ゾーンにも負荷集中や制御系の依存で性能低下が波及。他リージョンへの影響は確認されていない。
- 復旧状況: 復旧済み。再発防止策(PLC設定の全世界点検は11/15予定など)を実施中。
- 補足: 先週(10/22付)の記事では掲載できていなかった案件のため、今回続報として記載。
- 出典: https://status.cloud.google.com/incidents/Xs2XTHzAVC9YnafnPyzj / https://www.bbc.com/news/articles/cxdd8mm6qy4mo / https://www.thousandeyes.com/blog/google-cloud-outage-analysis-october-20-2026

### 2. Microsoft Teams: 米国の一部ユーザーで障害(10/26)
- 対象: Microsoft Teams(インシデント番号TM1526111)。
- 原因: 公表なし。自動スケーリング(負荷に応じて処理能力を自動で増やす仕組み)で回復したと説明。
- 影響範囲: 米国の一部ユーザー。具体的な機能・人数は未公表。サイバー攻撃を示す情報もなし。
- 復旧状況: 復旧済み。
- 出典: https://cybersecuritynews.com/microsoft-investigation-teams-issue/

### 備考
- AWSは今週の大規模障害を確認できず。Cloudflareは細かな障害・性能低下の報告が続いたが、大規模な全面停止は確認できず(第三者の監視サイト情報のため参考程度)。Microsoft 365のCopilot障害(10/28)は、1分で「実際には障害なし」と判定された誤報でした。

## 🇯🇵 日系企業系

### 1. ドコモ: 携帯電話の音声通話がつながりにくい障害(10/28)
- 発生: 10/28 16:30頃〜17:29頃(約1時間。報道ベース)
- 対象: ドコモ回線とドコモ回線を使うMVNO(格安SIM)の携帯電話サービス。
- 影響: 音声通話がかけにくい状況。緊急通報(110番・119番)も一部で利用しづらかったと公式に案内された。
- 原因: 検索範囲では未確認。
- 復旧状況: 復旧済み。
- 出典: https://www.docomo.ne.jp/info/network/ / https://k-tai.watch.impress.co.jp/docs/news/2152001.html

### 2. au・UQ mobile: メールサービス障害(10/28)
- 発生: 10/28 6:00頃〜13:40(約7時間40分)
- 対象: auとUQ mobileのキャリアメール(auメール持ち運びサービス含む)。音声通話とデータ通信は正常。
- 影響範囲: 全国。受信待ちだったメールは順次配送されたが、届くまで時間がかかる場合があった。
- 原因: メール設備の処理負荷が高い状態が継続。不正侵入は確認されていないとKDDIが説明。
- 復旧状況: 13:40に復旧。
- 出典: https://news.kddi.com/important/news/important_202610281835.html / https://www.yomiuri.co.jp/economy/20261028-GYT1T00283/

### 3. ドコモSMTBネット銀行: 一部サービスがつながりにくい障害(10/23)
- 発生: 10/23 16:30頃から(SNSで不具合報告が急増)。連携先のPayPayの緊急メンテは17:10〜17:45、Kyashの入金エラー解消は17:45頃。
- 対象: ドコモSMTBネット銀行(旧住信SBIネット銀行)のアプリ・サイト・ATM・決済連携。
- 影響: 残高照会エラー、ATM・決済が使えない、PayPay/Kyashへのチャージ・入金不可など。
- 原因: 検索範囲では公表を確認できず。
- 復旧状況: 連携先の案内から、17:45頃には連携機能が回復した模様(銀行本体の公式復旧時刻は未確認)。9/25にも同種の障害があり、今月で2回目。
- 出典: https://paypay.ne.jp/notice/20261023/m-08/ / https://www.kyash.co/maintenance/20261023 / https://newsdigest.jp/news/678d0514-fa3c-429b-b704-0e66f616982b

## 所感(今週の傾向)
- 通信キャリアの障害が1日(10/28)に2社同時期で発生。ただしauは「メール」、ドコモは「音声」と範囲が違い、原因も別とみられます。「つながるのが当たり前」な基盤ほど、緊急通報への影響など社会的インパクトが大きいと改めて分かります。
- Google Cloudの事例は、クラウド障害の原因が実はデータセンターの電源制御という物理側にあることを示しました。ゾーンを分けて設計していても、制御系や負荷集中で他ゾーンに波及するため、リージョン分散まで考えた構成が重要です。
- ドコモSMTBネット銀行は1か月で2回目の障害で、PayPay等の連携サービスにも波及しました。金融は連携先まで含めた依存関係の把握が大切です。
