# 技術検討: Hermes公式Androidアプリ（Termuxベース）（2026-08-28）

## これは何か

**「Hermes Agent - Android」**は、Nous Research公式のAndroidアプリ（Google Play配信）で、Hermes Agent本体をスマートフォン上で直接動かすためのものです。内部的には**Termux**（Android上でLinux相当の環境を再現するターミナルエミュレータ）を土台にしており、スマホの中に小さなLinuxサーバーを立てて、その上でHermes Agentのコマンドライン版を動かす仃組みです。

Nous Researchの公式ドキュメント上、Android/Termuxは**「Tier 2プラットフォーム」**と明記されています。つまり「一応動くように整備されているが、best-effort（ベストエフォート）扱いであり、デスクトップ/サーバー版ほどの品質保証はない」という位置づけです。

## どんな機能を実現するものか

Termux版でテスト・サポートされている機能:

| 機能 | 状態 |
|---|---|
| Hermes CLI本体 | ✅ サポート |
| cron（定期実行） | ✅ サポート |
| PTY／バックグラウンドターミナル | ✅ サポート |
| Telegramゲートウェイ | ✅ サポート（手動・best-effort） |
| MCP連携 | ✅ サポート |
| メモリ機能（Honcho） | ✅ サポート |
| ACP連携 | ✅ サポート |

**サポート対象外の機能:**

| 機能 | 状態・理由 |
|---|---|
| `.[all]`（フル機能セット） | ❌ Android非対応 |
| **音声機能（`voice`エクストラ）** | ❌ **未サポート**。`faster-whisper`が依存する`ctranslate2`ライブラリがAndroid向けにビルド提供されていないため |
| ブラウザ自動化（Playwright） | ❌ Termuxインストーラーでスキップされる |
| Dockerによるターミナル分離 | ❌ Termux内では利用不可 |
| バックグラウンド常駐 | △ Androidが積極的にTermuxのバックグラウンド処理を停止させるため、「常時起動し続けるサービス」としての安定動作は保証されない |

## 今回のユースケースにおける結論

**本タスク（ウェイクワードでの音声起動）には使えません。** 理由は明確で、公式ドキュメントに「`voice`エクストラは`ctranslate2`のAndroidビルドが存在しないため未サポート」と明記されているためです。音声認識（STT）自体がAndroid上のTermux環境では動作しない設計になっています。

このアプリは「スマホの中でHermesのテキストベースCLIを動かしたい」というユースケース（外出先でSSHの代わりにスマホ単体で作業する等）には有効ですが、今回のような音声・常時待ち受け系の用途には不向きです。

## 導入の条件・制約

| 項目 | 内容 |
|---|---|
| インストール方法 | Google Play公式アプリ、またはF-Droid版Termux＋手動インストールスクリプト |
| 対応OS | Android（Termuxが動作する範囲） |
| 前提知識 | Linuxコマンドライン操作の基本知識があると扱いやすい |

## 導入時のデメリット・リスク

- **Tier 2扱い**: mainブランチへのコミットで、Termux向けパッケージが予告なく壊れる可能性がある旨が公式に明記されている
- **機能制限**: 音声・ブラウザ自動化・Docker分離など、デスクトップ版で使える主要機能の一部が使えない
- **コミュニティ製パッケージ配布への依存**: `pkg install hermes-agent`形式のAPTリポジトリはNous Research公式ではなく、コミュニティ運営（第三者の署名鍵を信頼する必要がある）

## 運用時のデメリット・リスク

- **バックグラウンド停止**: Androidの省電力機構により、画面消灯時や長時間放置時にTermuxのプロセスが強制終了されやすく、「常時稼働するサービス」としての信頼性が低い
- **電池・ストレージ消費**: フルのLinux環境をスマホ上で動かすため、通常のアプリより電池・ストレージ消費が大きくなりやすい
- **アップデート追従の不確実性**: Tier 2のため、Hermes本体の更新に対してTermux版が追従しない期間が発生しうる
