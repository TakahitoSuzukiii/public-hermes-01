## 1. ITインフラ/サーバ運用保守のルーティンワーク自動化（PPT・Excel特化）

### 本当に週3時間削減できるのか？Claude CodeでExcel集計・週次レポート作成を自動化した話
- 出典: https://zenn.dev/makolab/articles/d16e46ea39edaa
- 内容: プログラミング未経験の筆者が、月次の売上データ集計・複数支店ファイルの統合・グラフ付きレポート生成という一連の作業を、Claude Codeとの対話だけで段階的に自動化していった記録。最初は単純な集計指示から始め、徐々にファイル統合やグラフ生成まで範囲を広げた過程が時系列で追える構成です。
- 便利さ: 「エンジニアではない担当者が、手探りでどこまで自動化を進められるか」という現実的なロードマップが分かる点が貴重です。IT部門に依頼せず現場主導でExcel業務を効率化したい場合の第一歩として参考になります。
- 注意点: 複数支店のファイル形式・列構成が揃っていることが前提の自動化のため、社内のExcelフォーマットがバラバラな場合は、まず表記統一のルール作りから着手する必要があります。

## 2. ゼロデイ攻撃対策・セキュリティ運用の自動化

### 「熟練した人間の対応では遅い」OSSから500件の脆弱性を掘り起こした「Claude Code Security」
- 出典: https://atmarkit.itmedia.co.jp/ait/articles/2603/30/news076.html
- 内容: Anthropicが2026年2月に限定プレビューを開始したWeb版Claude Codeの新機能「Claude Code Security」が、オープンソースソフトウェア（OSS）のコードベースを横断的にスキャンし、修正パッチ案の提示まで自動で行った結果、500件規模の脆弱性を発見したという事例を報じた記事。
- 便利さ: 「人間のセキュリティレビューでは追いつかない規模・速度」を実データで示している点が説得力があり、脆弱性の"発見から修正案提示まで"を自動化するイメージが具体的に掴めます。ゼロデイ攻撃（未修正の脆弱性を悪用する攻撃）が発覚してから対応するのではなく、事前に自動スキャンで潜在的な穴を洗い出す運用への転換材料になります。
- 注意点: 限定プレビュー段階の機能であり、検出された脆弱性の中には誤検知（false positive）も含まれる可能性があるため、修正パッチの自動適用ではなく、必ず人間によるレビューを経てからマージする運用が前提です。

## 3. インフラ/クラウドエンジニア・SRE・CI/CD・Playwrightによる自動化

### SRE業務をClaude Code + Terraformで実践するための覚書
- 出典: https://note.com/varu3/n/ncdb5a740124a
- 内容: SRE（Site Reliability Engineering＝サイト信頼性エンジニアリング）担当者が、Claude Code の有償プラン（Max）を1か月間集中的に業務利用した実務メモ。既存AWSリソースをTerraform（インフラをコードで管理するツール）にインポートする面倒な作業を、Claude CodeがAWS CLIから情報を取得し自動でHCL（Terraformの設定言語）を書く形で効率化した経験のほか、障害対応・エラー調査・コスト削減など幅広いSRE業務での活用場面が紹介されています。
- 便利さ: 開発者向けの活用事例が多い中で、SRE業務特化の一次体験談は希少です。「既存リソースのTerraformインポート」という地味だが手間のかかる作業を自動化できる具体例は、同じ悩みを持つインフラ担当者にそのまま刺さる内容です。
- 注意点: Claude Codeが生成したHCLやAWS CLIの操作は、本番環境に直接適用する前に必ず`terraform plan`（変更内容の事前確認コマンド）で差分を確認し、意図しないリソース変更が含まれていないかをチェックする必要があります。

### Terraform未経験の運用エンジニアが、Claude Codeを活用してインフラ構築した話
- 出典: https://quo-digital.hatenablog.com/entry/2026/02/05/144740
- 内容: QUO CARD デジタルイノベーションラボの運用エンジニアが、「大量メール送信時のバウンスレート（メール到達不能率）上昇」という課題に対し、日常的にTerraformを扱わない立場からClaude Codeを相棒にインフラ環境を構築して解決した事例。運用チーム（監視・運用設計が主業務）がインフラチーム領域に踏み込んだ経緯が具体的に語られています。
- 便利さ: 「運用担当者がインフラコードを書けるようになる」というスキルの垣根を下げる実例で、専門チームへの依頼待ちが発生しがちな体制の企業にとって、部門間の作業分担を見直すきっかけになります。
- 注意点: 未経験者がAI支援で本番インフラに変更を加える場合、レビュー体制（インフラチームによる最終承認等）を必ず設けないと、意図しない設定ミスがサービス影響に直結するリスクがあります。

## 4. ベストプラクティス、実際に構築・検証して効果があった手順書/実績

### Claude Coworkセキュリティガイド｜企業導入時の権限・監査・Chrome連携リスク
- 出典: https://nexaflow.io/blog/guide/claude-cowork-security
- 内容: cowork（Claude Desktop上で動く自律型AIエージェント機能）を企業導入する際の権限設計・監査ログ・Chrome連携リスクを整理した独立系ブログの解説記事。「読む・整理する・下書きする」範囲では導入価値があるとしつつ、Computer use（AIによるPC画面の直接操作）とClaude in Chrome（ブラウザ連携機能）については、2026年5月時点でCowork activityがCompliance API（監査ログ収集の仕組み）に記録されないことを理由に、業務端末への導入に慎重な立場を取っています。
- 便利さ: 「AIエージェントに何をどこまで任せるか」という権限設計（承認境界）の考え方を、VM（隔離された仮想環境）・ローカルファイル・Computer use・MCP（外部サービス連携規格）という4つの仕組みに分解して整理しており、社内導入検討時のチェックリストとして活用できます。
- 注意点: この記事は独立系ブログの見解であり、Anthropic公式のセキュリティ仕様とは区別して読む必要があります。導入判断は必ずAnthropic公式ドキュメントの最新情報と照らし合わせて行ってください。

## 5. GitHubのawesomeシリーズ

### awesome-claude-skills（ComposioHQ）
- 出典: https://github.com/ComposioHQ/awesome-claude-skills
- 内容: Claude Skills（Claude.aiやClaude Code、さらにCodex・Cursor・Gemini CLIなど他のコーディングエージェントでも使える再利用可能な作業手順定義）を1000件以上収録した大規模キュレーションリスト。外部サービス連携用の「connect」、Composio社製の「composio-skills」、コミュニティ共有の「skill-share」などカテゴリ別にディレクトリが分かれています。
- 便利さ: 前週紹介したSubagent系リスト（VoltAgent）とは異なる切り口で、「Claudeに繰り返し作業のやり方そのものを覚えさせる」Skills機能に特化しており、1000件超という規模から自社業務に近いテンプレートを見つけやすい点が魅力です。マルチエージェントツール横断で使える設計も汎用性が高いです。
- 注意点: 件数が非常に多く更新頻度も高いため、導入前にはREADMEやライセンス表記を個別に確認し、信頼できる作者・メンテナンス状況のSkillsから優先的に試すのが安全です。
