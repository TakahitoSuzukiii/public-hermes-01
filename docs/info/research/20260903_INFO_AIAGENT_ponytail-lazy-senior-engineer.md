# ponytail — 「怠惰なシニアエンジニア」を演じるAIエージェント用ルールセット

作成日: 2026-09-03 / STATUS: INFO / TOPIC: AIAGENT

> 出典: [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)（GitHub、115,035 stars / JavaScript、2026-08-28時点）

---

## 概要

`ponytail` は、Claude Code や Codex などのAIコーディングエージェントに「**最も怠惰な（でも有能な）シニアエンジニア**」のように振る舞わせる、プロンプト／ルールセットです。実行可能なコード生成ツールというより、AIエージェントに読み込ませる**行動指針（スキル）**に近いものです。

## コンセプト:「書かないコードが一番良いコード」

AIコーディングエージェントは、放っておくと**過剰に作り込みすぎる**傾向があります（不要なヘルパー関数、独自実装、過剰な抽象化等）。ponytailは、それに対して「本当にこの機能は必要か？」「すでにあるものを使い回せないか？」と**7段階のはしご（ladder）**を登らせてから初めて新規コードを書かせる、という制約を課します。

**7段階のはしご（概要）:**
1. そもそも今この機能は必要か？（投機的な実装を避ける）
2. 既存のコード内に使えるヘルパーはないか？
3. 標準ライブラリ（stdlib）で足りないか？
4. プラットフォームのネイティブ機能で足りないか？
5. 外部ライブラリに頼るべきか？
6. …と、段階を踏んで「本当に必要な最小限のコード」だけを書かせる

## 重要な注意点:「怠惰」だが「手抜き」ではない

READMEに明記されている原則:

> 「Lazy about the solution, never about reading. Lazy, not negligent（解決策には怠惰でも、読解には怠惰ではない。怠惰であって、いい加減ではない）」

つまり、**信頼境界のバリデーション・データ損失対策・セキュリティ・アクセシビリティは絶対に手を抜かない**、という線引きが明記されています。「楽をする」のはコード量であって、安全性ではないという設計思想です。

## 実測された効果（公開データ、FastAPI+Reactの実リポジトリで検証）

Claude Code（Haiku 4.5）で12種類の機能タスクを、ponytail適用あり／なしで比較した結果:

| 指標 | 効果 |
|---|---|
| コード量 | 平均**約54%削減**（過剰実装が起きやすいタスクでは最大94%削減） |
| コスト | 約**20%削減** |
| 速度 | 約**27%向上** |
| 安全性 | **100%維持**（セーフティ機能は削らない） |

## なぜ今、これが支持されているのか

AIコーディングエージェントの普及により、「エージェントに書かせたコードがどんどん肥大化していく」という新しい種類の技術的負債が問題視され始めています。人間のエンジニアがレビューで「これ本当に必要？」と聞くのと同じ役割を、プロンプトレベルでエージェントに事前に問わせる、というアプローチが評価されている背景があります。

## この考え方との接続（本サイト運用方針との整合性）

本サイト（Prime／Hermes Agent運用）の `AGENTS.md` に明記されている以下の方針と、思想的に近い考え方です:

- **追加のみ・デグレ無し:** 新機能は原則「追加」で実装し、既存ロジックを書き換えない
- **最小構成・最小変更・最小リソース:** 必要最低限の構成を採り、保守性を最優先。過剰な依存・抽象化を避ける

ponytailの「7段階のはしご」は、この「最小構成・最小変更」という方針を、AIエージェント自身に事前チェックさせる仕組みとして具体化したものと捉えられます。実際の導入検討にあたっては、外部スキル導入時の信頼性チェック（スター数・作者情報・メンテナンス状況・ライセンス・コード内容）を経てから判断する運用です。
