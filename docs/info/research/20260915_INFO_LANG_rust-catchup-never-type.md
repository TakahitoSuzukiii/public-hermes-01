## なぜ今、Rustが話題なのか

### 1. MicrosoftがRustを「Tier-1言語」に格上げ

Windows開発環境において、C++等と並ぶ第一級のサポート対象言語として正式に位置づけられた。Microsoftは以前から「Rustはメモリ安全性に起因する深刻なセキュリティバグの多くを解決しうる言語」として注目しており(Project Veronaなどの取り組みでも言及)、大手ベンダーが本腰を入れて採用するフェーズに入ったことを示す象徴的な出来事といえる。

### 2. Ubuntu 26.10で、Linuxの基本コマンド群のRust化が完了

従来C言語(GNU coreutils)で書かれてきたOSの根幹コマンド(`cp`・`mv`・`rm`等)が、Rust製の`uutils coreutils`へ置き換えられた。Ubuntu 25.10の時点で`ls`・`cat`・`chmod`・`du`等は既に移行済みで、26.10でセキュリティ上の懸念から見送られていた`cp`・`mv`・`rm`の移行が完了し、GNU Core Utilitiesからの脱却が完了した。日常的なコマンド操作の見た目は変わらないが(`uutils`はGNU互換のドロップイン置き換えとして設計されている)、内部実装がメモリ安全な言語に置き換わったことになる。「動くコードを書き換えてまで採用する価値がある」と、Linuxディストリビューションの中核で判断された事例。

### 3. Never型(`!`)の安定化

10年がかりの言語仕様の成熟。詳細は次章で解説する。Rustという言語自体が「実験段階」を抜け、着実に完成度を高めているフェーズにあることを示している。

## Rustとは何か(基本の位置づけ)

**「システムプログラミング言語」**というジャンルに属する。OS、ブラウザのコア部分、コマンドラインツール、組み込み機器など、**速度と安全性の両方が強く求められる領域**で使われる言語。C/C++が伝統的に担ってきた領域の、より安全な後継として急速に採用が広がっている。

### 最大の特徴:「ガベージコレクタなしで、メモリ安全性を保証する」

多くのモダンな言語(Python、Java、Go等)は「ガベージコレクタ(GC)」という仕組みで、使わなくなったメモリを自動的に片付ける。しかしGCには、**動作タイミングが読めず処理が一瞬止まる**というデメリットがある。

一方、C/C++はGCがない代わりに、**メモリの管理をすべて人間が手動で行う**必要があり、「メモリを二重に解放してしまう」「解放済みのメモリに誤ってアクセスする」といった、深刻なセキュリティ脆弱性の温床になってきた。

**Rustは、この二択に対する「第三の答え」を提示した言語である。**「所有権(ownership)」という独自の仕組みを使い、**コンパイル時(プログラムを実行する前の段階)に、メモリの安全性をチェックし尽くす**ことで、GCなしで、かつ手動管理の危険性もない、という両立を実現している。実行時のオーバーヘッドがほぼゼロなので、パフォーマンスもC/C++並みに高速。

## Never型(`!`)とは何か

### 一言でいうと

**「絶対に値を返さない」ということを、型として表現する仕組み。** Rustでは`!`という記号で書く。

### 具体的にどんな場面で使うか

普通の関数は何かしらの値を返す。しかし、以下のような**「関数の途中で処理が終わってしまい、最後まで到達しない」**関数がある。

- `panic!()`(エラーで強制終了する)を呼ぶだけの関数
- 無限ループ(`loop {}`)で永遠に処理を続ける関数
- `std::process::exit()`でプログラム自体を終了させる関数

これらは「値を返す」という概念自体が成立しない。**Never型はこの「絶対に値を返さない」という性質そのものを、コンパイラに伝えるための型**である。

```rust
fn always_panics() -> ! {
    panic!("ここで終わる");
}
```

### なぜこれが便利なのか

Never型の最大の特徴は「**どんな型にでも化けられる**」という性質である。例えば以下のようなコード:

```rust
let x: i32 = if some_condition {
    42
} else {
    panic!("失敗")  // ← ここはNever型
};
```

`if`の両方の分岐は「同じ型」である必要があるが、`panic!`側は「そもそも値を返さない」ので、コンパイラは**Never型を`i32`として扱ってよい、と判断**できる。これにより、「片方は正常値、もう片方はエラーで即終了」という頻出パターンを、型エラーなしで自然に書けるようになる。

### 今回、何が「安定化」したのか

この概念自体は10年前から存在し内部的には使われていたが、**開発者が自分のコードの中でこの型を明示的に書いて活用することは、長らく「実験的機能(unstable)」扱い**だった。今回(2026年8月、Rust 1.100向け、PR #155499がマージ)、**10年越し・5回目の挑戦でついに正式機能(stable)として使えるようになった**。

**注意が必要な変更点:** これまでコンパイラが「型が決まらない」場面で暫定的に「空のタプル`()`」を選んでいた挙動が、今回から「Never型」を選ぶように変わった。これは**破壊的変更(breaking change)**で、実際に大規模検証(crater — 公開されている多数のクレートを対象にした自動テストツール — で当初3,277個のクレートに影響が出ることが判明)が行われた末に、段階的に導入されている。標準ライブラリの`std::convert::Infallible`も、今回からNever型そのものの別名(エイリアス)になった。

「10年かけて、実際に多くのコードを壊さないよう慎重に検証しながら進める」という、Rustらしい安定化プロセスの好例といえる。

## 学習の始め方(公式ルート)

1. **公式の入門書「The Rust Programming Language」**(通称「The Book」)を読む
   - <https://doc.rust-lang.org/book/>
   - 無料・オンラインで読める公式テキスト。Rust学習者のほぼ全員が最初に触れる定番教材
2. **公式ツールチェーン`rustup`をインストール**して、実際に手元で動かしながら学ぶ
3. 最初の壁になりやすいのが「**所有権(ownership)」「借用(borrowing)」「ライフタイム(lifetime)**」という3つの独自概念。ここでつまずく人が非常に多いが、逆に言えば**この3つさえ理解すれば、Rustの安全性の仕組みの大部分を理解したことになる**

### 押さえておきたい周辺情報

- **`cargo`**:Rust公式のパッケージ管理・ビルドツール。プロジェクトの作成、依存ライブラリの追加、ビルド、テストまで一手に担う、非常に評判の良いツールチェーン
- **エディション制度**:Rustは2015・2018・2021・2024と、数年おきに「エディション」という区切りで言語仕様を進化させている。学習する際は、教材がどのエディション向けかを意識すると混乱が減る

## まとめ:今Rustを学ぶ意義

- **OS・ブラウザ・インフラの根幹**で採用が広がっており、今後さらに重要度が増す領域
- **メモリ安全性を型システムで保証する**という設計思想は、C/C++以外の言語を使っている人にとっても、「安全なコードとは何か」を学ぶ上で非常に良い教材になる
- Microsoft・Ubuntu(Canonical)といった大手が本格採用に舵を切ったことで、**「一部の愛好家の言語」から「実務で確実に必要とされるスキル」へと転換しつつある**段階
