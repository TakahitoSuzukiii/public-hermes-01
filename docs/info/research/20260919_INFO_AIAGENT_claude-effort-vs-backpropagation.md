# Claudeの「Effort(エフォート)」パラメータとは? 誤差逆伝播法との違いも整理

- **記録日:** 2026-09-19
- **位置づけ:** Claude(Anthropic社のAIモデル)チャット・API利用時に設定できる「Effort」パラメータについての調査。名前が似ている・混同されやすい「誤差逆伝播法(バックプロパゲーション)」との違いも合わせて整理する。Prime自身も本セッションで`reasoning_effort`という概念で動作している、実務に直結するテーマ。

## 1. Effort(エフォート)パラメータとは何か

Anthropic公式ドキュメント(2026年時点)によれば、**Effortパラメータは「Claudeが応答時に消費するトークン数をコントロールする設定」**。1つのモデルのままで、**「応答の丁寧さ・徹底度」と「トークン効率(速度・コスト)」のトレードオフ**を調整できる仕組みとして提供されている。

APIでは`output_config.effort`という形でリクエストに含める。

```python
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=4096,
    messages=[{"role": "user", "content": "マイクロサービスとモノリシックの比較を分析して"}],
    output_config={"effort": "medium"}
)
```

## 2. Effortの5段階(公式ドキュメントの定義)

| レベル | 説明 | 典型的な用途 |
|---|---|---|
| **max** | トークン消費に一切制約を設けない、絶対的な最大能力 | 最も深い推論と、最も徹底的な分析が必要なタスク |
| **xhigh** | 長時間タスク向けの拡張能力(一部モデルのみ対応) | 30分を超える長時間のエージェント・コーディング作業、数百万トークン規模の予算 |
| **high** | タスクが必要とする分だけトークンを使い、優れた結果を出す。**多くのモデルでデフォルト** | 複雑な推論、難しいコーディング問題、エージェントタスク |
| **medium** | 速度・コスト・性能のバランスを取った中庸なアプローチ。**Claude Opus 5.5ではデフォルト** | 速度・コスト・性能のバランスが必要なエージェントタスク |
| **low** | 最も効率的。トークン消費を大幅節約する代わりに、能力がやや落ちる | サブエージェントなど、速度と低コストを最優先すべきシンプルなタスク |

**重要な注記(公式ドキュメントより):** Effortは**「厳密なトークン予算」ではなく、"行動上のシグナル(behavioral signal)"**である。低いEffortレベルでも、Claudeは十分に難しい問題には引き続き思考(thinking)を行う。ただし、同じ問題であれば、高いEffortレベルの時より思考量は少なくなる、という違い。

## 3. 何のために存在するのか:「1つのモデル」で「複数の振る舞い」を実現する仕組み

従来、AIモデルを使う開発者は「どのモデル(軽量版か高性能版か)を選ぶか」という選択でコスト・速度・品質のバランスを取っていた。**Effortパラメータは、モデル自体を切り替えずに、同じモデルの中で"どれだけ深く考えるか"を調整できる**という点が新しい。

- 簡単な質問やルーティン作業には`low`にして高速・低コストに
- 複雑なコーディングや長時間のエージェントタスクには`high`〜`max`にして、時間とコストをかけてでも精度を優先
- **サブエージェント(小さな下請けタスクを処理する仕組み)には`low`が推奨される**という記載もあり、実務では「タスクの重要度・複雑さに応じて動的にEffortを切り替える」運用が想定されている

## 4. Effortと「Thinking(思考)」の関係

Effortは、Claudeの**拡張思考(extended thinking、応答前に内部で段階的に考えるプロセス)の深さをコントロールする、推奨される主要な手段**として位置づけられている。従来は「thinkingのトークン予算」を直接数値で指定する方法もあったが、公式ドキュメントは**「Adaptive thinking(適応的思考)が使える場面では、Effortを使うことが推奨される」**としている。

## まとめ:Effortパラメータの本質

**「同じ頭脳(モデル)のまま、どれだけ真剣に考えさせるかを指示するダイヤル」**というのが最も直感的な理解。人間で例えるなら、「ざっくりでいいから今すぐ答えて」と頼むか、「時間をかけてじっくり検討してから答えて」と頼むかの違いに近い。

## 5. 「誤差逆伝播法(バックプロパゲーション)」との違い:全く別の階層の話

「Effort」と「誤差逆伝播法」は、**名前も概念も全く別物だが、どちらも「AIの"考える深さ・学習の仕方"に関わる話」という共通点があるため、混同されやすい**。両者の違いを整理する。

### 誤差逆伝播法(Backpropagation)とは

**ニューラルネットワーク(人工知能モデルの内部構造)を"学習させる"ためのアルゴリズム**。モデルが出した予測と正解の差(誤差)を測定し、その誤差を**ネットワークの出力側から入力側へ逆向きに伝播させながら、各層の重み(パラメータ)をどの方向にどれだけ調整すべきかを計算**する。この計算結果をもとに、モデルの内部パラメータを少しずつ更新していくことで、モデルは徐々に「正しい答えを出しやすい」状態へ近づいていく。

- 数学的には**連鎖律(chain rule、微分の合成関数の法則)**を使って、各層の勾配(誤差に対する感度)を効率的に計算する手法
- これは**モデルの"学習フェーズ"(訓練時)に行われる処理**であり、ChatGPTやClaudeのような大規模言語モデルも、この仕組みを使って何兆ものパラメータを訓練されている
- 1度学習が完了したモデル(いわゆる「学習済みモデル」)を、ユーザーが実際にチャットで使う際には、**誤差逆伝播法は一切動いていない**

### 決定的な違い:「いつ」「何のために」動くか

| 観点 | 誤差逆伝播法(Backpropagation) | Effortパラメータ |
|---|---|---|
| **動作するタイミング** | **モデルの学習(訓練)フェーズ**。開発者側がモデルを作る過程で使う | **モデルの推論(利用)フェーズ**。ユーザーがチャット・APIを使う都度 |
| **目的** | モデルの内部パラメータ(重み)を、正解に近づくよう**永続的に**調整する | 既に学習済みのモデルが、**1回の応答を生成する際にどれだけ思考トークンを使うか**を一時的に調整する |
| **影響範囲** | モデル自体が恒久的に変化する(再学習しない限り元に戻らない) | その場限りの設定。次の会話・リクエストではまた自由に変えられる |
| **誰が操作するか** | AI開発企業(Anthropic等)のエンジニアが、モデル開発時に行う | エンドユーザー・開発者が、API利用時・チャット利用時に指定する |
| **計算の中身** | 勾配計算(微分)+重み更新(最急降下法等の最適化アルゴリズム) | 生成時にどれだけ「拡張思考」のステップを踏むかという、生成プロセスの制御 |

### たとえ話で理解する

- **誤差逆伝播法** = 生徒(モデル)が問題集を解いて、答え合わせをしながら「この考え方は間違っていた、次はこう考えよう」と**脳みその配線自体を作り変えていく、勉強・訓練のプロセス**
- **Effortパラメータ** = 既に勉強を終えた生徒(学習済みモデル)に対して、「この問題は簡単だからパッと答えて」「この問題は難しいから時間をかけてじっくり考えて」と、**その場その場で"どれだけ真剣に取り組むか"を指示すること**

つまり、**誤差逆伝播法はモデルが"賢くなる"ための土台作りの仕組み、Effortは既に賢くなったモデルの"どのくらい本気を出すか"を都度調整する運用上のスイッチ**という、全く異なるレイヤーの概念。
