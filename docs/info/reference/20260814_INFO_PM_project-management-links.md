#### トランスパレンシー(透明性)
- チームの状況・ロードマップをオープンにすること。

#### 検査と適応(インスペクトアンドアダプト)
- 定期的にチェックポイントを設け、状況を検査し、必要に応じて計画を調整する考え方。

#### 柔軟な対応
- 変化する要求に応じて計画を柔軟に見直す姿勢。

### 主なプラクティス

| プラクティス | 内容 |
|---|---|
| スプリント/開発サイクル | 計画・開発・テスト・デリバリーの繰り返し |
| プロダクトバックログ | 要求・要件・機能要件・非機能要件・優先順位の一覧 |
| 計画会議 | スプリントとバックログのレビュー |
| デイリースタンドアップ | 毎日の朝会 |
| スプリントレビュー | 成果物確認とフィードバック |
| レトロスペクティブ(振り返り) | 反省会。問題点と改善案を洗い出しブラッシュアップする |

### 大規模スクラムのフレームワーク

- [SAFe(Scaled Agile Framework)](https://www.atlassian.com/ja/agile/agile-at-scale/what-is-safe) — 大規模組織向けにアジャイルをスケーリングするフレームワーク
- [LeSS(Large-Scale Scrum)](https://www.atlassian.com/ja/agile/agile-at-scale/less) — 複数のスクラムチームが同じプロダクトを開発する方式
- [LeSS Hugeを参考にしたスクラムのスケーリング事例](https://tech.mirrativ.stream/entry/2023/05/23/100000)
- **Nexus** — 複数のスクラムチームが連携する大規模アジャイルフレームワーク
- **DAD(Disciplined Agile Delivery)** — カスタマイズ可能な大規模アジャイルフレームワーク
