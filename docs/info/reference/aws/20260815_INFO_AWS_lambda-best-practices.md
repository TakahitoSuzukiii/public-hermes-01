## 用語ミニ解説（初心者向け）

- **AWS Lambda**: サーバーを管理せずにコードを実行できる「サーバーレス」コンピューティングサービス。イベント（HTTPリクエスト、S3への配置等）をトリガーに関数が実行される。
- **コールドスタート（cold start）**: Lambda関数が久しぶりに呼ばれた際、実行環境の初期化に時間がかかる現象。
- **実行環境の再利用（execution environment reuse）**: Lambdaは一度起動した実行環境を一定時間再利用する。この特性を踏まえた設計がパフォーマンス最適化の鍵になる。

## 1. 公式ベストプラクティスの要点

[AWS公式ドキュメント](https://docs.aws.amazon.com/ja_jp/lambda/latest/dg/best-practices.html) に基づく主要な推奨事項を整理する（2026年8月時点の最新版に準拠して要点を確認）。

### 関数コードの設計

- **ハンドラー関数とビジネスロジックを分離する**: テストしやすくなり、Lambda固有の依存を減らせる
- **実行環境の再利用を前提に、SDKクライアントやDB接続はハンドラー外（グローバルスコープ）で初期化する**: 呼び出しごとに再接続するコストを避けられる
- **べき等性（同じ入力に対して何度実行しても同じ結果になる性質）を持たせる**: リトライやイベント重複配信に対する安全策
- **一時的な状態はハンドラー内に閉じ込める**: 実行環境が再利用された際に前回の状態が残っていて事故になるのを防ぐ

### パフォーマンス・コスト

- 必要以上に大きいメモリ設定を避け、実測に基づいてメモリ・タイムアウトを調整する（LambdaはメモリサイズとCPU割当が比例するため、メモリを上げると処理時間が短縮され結果的にコストが下がるケースもある）
- 依存パッケージを最小限にし、デプロイパッケージのサイズを小さく保つ（コールドスタート時間に影響）
- 頻繁に呼ばれる処理は Provisioned Concurrency（事前にウォームな実行環境を確保する機能）の利用を検討する

### 権限・セキュリティ

- 実行ロールには必要最小限のIAM権限のみ付与する（最小権限の原則）
- 環境変数に秘密情報を平文で置かず、AWS Secrets Manager / Systems Manager Parameter Store と連携する
