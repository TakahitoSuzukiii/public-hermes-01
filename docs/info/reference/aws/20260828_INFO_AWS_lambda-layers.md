# AWS Lambda レイヤー（Lambda Layers）調査メモ

作成日: 2026-08-28
ステータス: INFO（情報共有・技術調査結果）

## 概要

AWS Lambda の「レイヤー（Layer）」は、複数の Lambda 関数で共通利用できるライブラリ・ランタイム・カスタムコードなどを、関数本体のデプロイパッケージとは別に外部化して管理できる仕組みです。

## 目的

- 関数のデプロイパッケージのサイズを小さく保つ
- 共通の依存ライブラリ（例: `requests`、`pandas` など）を複数の関数で使い回す
- ライブラリのバージョン管理を関数コードと分離して行う

## 仕組み

ライブラリ一式を zip 形式でまとめ、Lambda コンソールまたは AWS CLI でレイヤーとして登録します。Python の場合は `python/` ディレクトリ配下にパッケージを配置して zip 化するのが一般的な構成です。

登録したレイヤーを Lambda 関数にアタッチすると、関数コード内でそのライブラリを通常どおり `import` して使用できます。

## 作成手順（CLI 例・Python の場合）

```bash
mkdir -p python
pip install requests -t python/
zip -r layer.zip python
```

上記で作成した `layer.zip` を AWS CLI や コンソールからレイヤーとして登録し、対象の Lambda 関数にアタッチします。

## 制限事項

- 1つの Lambda 関数にアタッチできるレイヤーは**最大5つ**まで
- レイヤーを含めた関数の展開後（unzip後）の合計サイズは**250MB**まで

## メリット

- 共通ライブラリの重複管理が不要になる
- デプロイパッケージが軽量化され、コードの見通しが良くなる
- レイヤーごとにバージョンが付与されるため、バージョン管理がしやすい
