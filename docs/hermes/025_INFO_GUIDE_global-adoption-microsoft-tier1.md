# Rustのグローバル採用実績とMicrosoft公式発表(Tier-1言語化)

- **記録日:** 2026-09-19
- **位置づけ:** Rustシリーズ第8弾。「そもそもRustはどれだけ実際に使われているのか」という一次情報(公式サーベイ・公式発表)に基づく調査。9/15の「Rustキャッチアップ」記事(016番)で触れたMicrosoftのTier-1格上げについて、その公式発表の詳細を深掘りする。

## 1. グローバルな採用実績:「State of Rust Survey 2025」(第10回)より

Rust公式チーム(Rust Survey Team)が2025年11月17日〜12月17日に実施した、**7,156件の回答**に基づく公式調査(2026年3月発表)が、最も信頼できる一次データ。

### 主要な数値

| 指標 | 数値 | 補足 |
|---|---|---|
| **企業でのRust「非自明な利用」割合** | **48.8%**(2023年比 +10ポイント) | 2023年は38.7%。調査チームは「構造的な市場浸透」と分析 |
| **Rustを日常的に使う開発者の割合** | **55.1%** | 4年間の調査で過去最高 |
| **自分をRustの生産的な書き手と評価する割合** | **56.8%**(2022年 42.3%から急伸) | |
| **導入が目標達成に役立ったと回答した企業** | **84.8%** | 既にRustを本番運用している組織のみ対象 |
| **導入コストに見合ったと回答した割合** | **78.5%** | |
| **もう一度導入するなら、との問いにYesと回答した割合** | **65.4%** | |
| **導入時に何らかの課題があったと回答した割合** | **31%** | |

### 企業でのRust活用領域(上位)

1. **サーバーサイド・バックエンドアプリケーション:51.7%**
2. **クラウドコンピューティングアプリケーション:25.3%**
3. **分散システム:約22%**
4. コンピュータセキュリティ
5. 組み込みシステム

→ **「メモリ安全性」と「性能」が絶対条件になる領域で特に強い**、という傾向がはっきり出ている。

### 導入していない企業の理由

**最多は「まだ手を付けていないだけ」(60.8%)**であり、「難しいから」「ライブラリが足りないから」「コミュニティへの懸念」といった消極的理由は少数派。これは**Rustへの評価が既に「様子見」から「時間の問題」へ移行しつつある**ことを示唆する。

### 専門家の見解(留保点も含めて公平に)

Forrester Researchのアナリスト、Andrew Cornwall氏はThe New Stackの取材に対し、**「Rustはエンタープライズで大規模採用されているとは見ていない」**とコメントしている。氏によれば、Rustは主に**「一部開発者にとってのCの代替」**として位置づいており、企業で書かれるコードの絶対量では依然としてPython・Javaが圧倒的に多いという。また、**Goも速度面で近く、ガベージコレクタにより人間・AIエージェント双方にとって開発しやすい**という点でRustと競合している、とも指摘している。

### その他の注目トレンド

- **コンパイル時間の遅さ**が依然として最大の不満点(27%超が「重大な問題」と回答)。ビルド成果物によるディスク使用量の多さも同様に課題
- 2025年に安定化した**let chains(複数条件をand結合できる構文)・async closures(非同期クロージャ)**は好評
- **開発者がコミュニティ(フォーラム・勉強会)よりも、ChatGPT・Claude・GeminiといったLLMに質問する傾向が強まっている**という、学習方法の変化も指摘されている

## 2. Microsoft公式発表:RustをTier-1言語に格上げ(2026年9月11日)

### 発表概要

2026年9月11日、**MicrosoftはRustを社内開発における「Tier-1言語」に正式に分類**した。これは**C++、C#、TypeScriptと同格**の、Microsoft社内で最も手厚い開発支援を受けられる言語という位置づけを意味する。

### 「Tier-1言語ステータス」とは何を意味するか

Microsoft社内での「Tier-1エンジニアリングステータス」とは、**「ローカル開発から本番投入までの、舗装された道(paved path)」**を意味する公式区分。具体的には以下が含まれる。

- セキュアなツールチェーンビルド
- 成熟した開発者向けツール群
- 確立された品質ワークフロー
- 深いプラットフォーム統合
- **Microsoft's Security Development Lifecycle(SDL)要件への準拠**

これまでこの地位にあったのは**C++、C#、TypeScriptの3言語のみ**であり、Rustが4番目としてここに加わった。

### 技術的な要:`rustc_codegen_utc`

発表の技術的中核は、**Rustコンパイラと、既存のWindows C++開発を支えるMSVCバックエンドを接続するコード生成バックエンド「rustc_codegen_utc」**をMicrosoftが独自開発したこと。これにより以下が実現される。

- Windowsの既存ツール群との互換性
- C++コードとの直接的な相互運用性
- 言語をまたいだ最適化・インライン化
- **デバッグ・プロファイリングのワークフローが2つではなく1つに統一される**

### 既に進んでいた社内浸透(Rust Foundation公式記事より)

Rust Foundationの公式まとめによれば、**RustはMicrosoft社内でRust 1.90以降セルフホスト(Rustコンパイラ自体をRustでビルド)されており、2026年初頭から本番運用可能な状態**にあった。発表時点で**社内100リポジトリ以上がRustで構築されており、毎週新しいリポジトリが追加されている**という。

### なぜ今このタイミングなのか:メモリ安全性への取り組みの延長線上

この決定は、**Microsoftが2019年に公表した「Microsoftが毎年パッチを当てる脆弱性のうち、約70%がC・C++のメモリ安全性問題(バッファオーバーラン、use-after-free等)に起因する」というデータ**に端を発する、長期的なメモリ安全性強化の取り組みの一環。

- **CISA(米国土安全保障省サイバーセキュリティ・インフラストラクチャセキュリティ庁)も、業界全体に対して新規のシステムコードにメモリ安全な言語を使うよう促す同様の主張を展開**している
- Microsoftは2026年5月には**C#にも同様のメモリ安全ツールを適用**しており、今回のRust Tier-1化は「**C#では届かない領域(Windows全体:ファームウェア・ドライバ、カーネル・ハイパーバイザ、マイクロサービス)**」を埋める次の一手と位置づけられている

### Rust vs C++:トレードオフの整理(記事内の分析)

| 観点 | Rust | C++ |
|---|---|---|
| メモリ安全性の保証 | **借用チェッカーによりコンパイル時に強制**(use-after-free、バッファオーバーランを含む) | 開発者の規律+サニタイザ・静的解析ツールに依存 |
| 学習コスト | 借用チェッカーの学習曲線が急 | 相対的になだらか(ただし習熟済みの人材プールが厚い) |
| 実務での人材プール | 本番経験のあるエンジニアはまだ少ない | 厚い人材プールが既に存在 |
| 運用コスト | 2つのツールチェーン・ビルド・セキュリティプロセスを並行維持する必要 | 既存資産をそのまま活用可能 |

記事は**「全てをRustに書き換える、という話ではない」**と明確に述べており、実務的な結論は**「攻撃対象領域が大きい新規コンポーネント(ドライバ、パーサー、ネットワーク接続コード)にはRustを選び、安定して深く相互接続されたC++システムには、特別なセキュリティ上の理由がない限り触れない」**という、段階的・限定的な導入方針が推奨されている。

### Microsoft単独の動きではない:Linuxカーネルとの連動

- **Linuxカーネルのメンテナーは、2025年のカーネルメンテナーサミット(東京開催)を経て、2025年12月にRustサポートを恒久化**した
- Rust for Linuxプロジェクトを主導するMiguel Ojeda氏は、カーネルのメーリングリストで**「実験は終わった。つまりRustはここに留まる」**と明言
- **Android 16の6.12カーネルを搭載した端末では、既にRust製のメモリアロケータコードが本番稼働中**であり、これは「研究室の話」ではなく、**現時点で数百万台規模のデバイスが実際にRustコードを動かしている**ことを意味する
- Linuxのメンテナーである Greg Kroah-Hartman氏は、**「Rust製のドライバは、実際にはC言語版より安全であることが実証されており、統合上の問題も予想より少なかった」**と述べている

## まとめ:2つの調査が示す共通の方向性

1. **公式サーベイ(State of Rust Survey)** → 企業の約半数(48.8%)が既にRustを非自明な形で利用、満足度も高い(84.8%が目標達成に貢献したと回答)
2. **Microsoft公式発表(Tier-1化)** → C++・C#・TypeScriptと並ぶ最上位の社内エンジニアリング支援をRustに付与、Windows全域にわたる段階的採用を明言
3. **Linuxカーネル側の動き** → 恒久サポート化、Android端末で既に本番稼働中

**業界最大級のプラットフォームベンダー2社(Microsoft・Linuxカーネルコミュニティ)が同時期に同じ方向(メモリ安全な言語をシステムコードの標準基盤へ)を示している**、というのがこの調査から見える最も重要な構造的トレンド。一方で、Forrester社のアナリストが指摘する通り、**「エンタープライズ全体でのコード量」という視点では、依然としてPython・Javaが主流であり、RustはあくまでCの代替として特定領域(メモリ安全性・性能が絶対条件の箇所)に浸透している**という、過大評価しすぎない視点も併記しておく。
