# 新AIモデル基盤「System One Models」と第一弾「Jev」を読み解く

- **記録日:** 2026-09-19
- **位置づけ:** Hacker Newsで1958pt・511コメントと非常に大きな反響を集めたTypeSafe AI社の発表記事「Introducing System One Models & Jev」(2026-09-15)を調査・要約。「LLM(大規模言語モデル)はチャットには強いのに、なぜ自動化がここまで進まないのか」という問いに対する、新しいアプローチの提案。AIエージェント(Prime)の運用・ガードレール設計とも関連するテーマとして記録。

## 発表の背景・発表者

創業者Diogo Almeida氏は、**OpenAIでChatGPTの元になった研究(指示追従・対話に強いモデルを作る手法)に携わった人物**。2年間のステルス期間を経て、TypeSafe AI社として初の「System One Model」というモデル分類と、その第一弾製品「Jev」を早期アクセス公開した。

## そもそも何が課題だったのか

**「言語モデルは何年も前からチャットで人間を超える性能を出せているのに、なぜ自動化(人手を介さない業務処理)はここまで進んでいないのか」**という問いが出発点になっている。著者は当初、チャットモデルの延長線上にAGI(汎用人工知能)があると考えていたが、そこには**根本的に欠けているものがある**と気づいたという。

## System One Modelsとは何か

**「ソフトウェアが直接利用できる、高速かつ構造化された意思決定を行うために作られた、新しいクラスの最先端モデル」**と定義されている。名称は行動経済学者ダニエル・カーネマンの著書『ファスト&スロー』における、**「速く直感的なシステム1思考」と「遅く熟慮的なシステム2思考」**の区別に由来する。

## 第一弾モデル「Jev」の特徴

名前は経済学者ウィリアム・スタンレー・ジェヴォンズ(石炭利用の効率化がかえって石炭需要を増大させた「ジェヴォンズのパラドックス」で知られる)にちなむ。**知能のコストが1桁下がるごとに、その分ユースケースが桁違いに広がる**という期待を込めた命名。

### 既存LLMとの構造的な違い(記事内の比較表を要約)

| 観点 | 既存LLM | Jev(System One Model) |
|---|---|---|
| **学習手法** | RLHF(人間フィードバックからの強化学習)/RLVR(検証可能な報酬からの強化学習) | **RLCD(Reinforcement Learning for Calibrated Decisions、較正済み意思決定のための強化学習)**という独自手法 |
| **最適化対象** | 人間の好み(文章・チャット応答の評価) | **較正された確率**(System 1的なタスクにおける、認識論的に正直な確率) |
| **出力形式** | 文字列(何でも生成できるが自由すぎる。コード、幻覚、拒否も含む) | **型安全な構造化された値**(あらかじめ定義された形式のみ、型エラーが起きない) |
| **サンプリング方式** | 逐次的(1トークンずつ、前のトークンに依存して生成) | **並列**(全ての出力を1回のクエリで同時生成) |
| **速度** | フロンティアモデルで応答に3〜329秒 | **70ms〜500ms**(同水準の知能で40〜200倍高速) |
| **コスト** | 入力トークン $0.20〜$10/百万トークン、出力はさらに約5倍 | 入力 $0.042/百万トークン、**出力は無料**(課金するには安すぎるため) |
| **確信度の表現** | 確信度を尋ねても、しばしば過信・不安定 | **常に較正された確信度と不確実性を伴って出力**(確信度が高いほど実際に正確) |

### 何を犠牲にしているか

Jevは**文字列(自由なテキスト)を生成する能力を手放している**代わりに、構造化出力に特化しており、**そもそも幻覚(ハルシネーション、事実に基づかない出力)を起こせない設計**になっているという。著者はこれを「フロンティア級の知能を持つ関数呼び出し」と例えており、**非構造化状態を入力し、型付きの確率的判断を出力する**というイメージで説明している。

## それぞれの得意領域(使い分けの提案)

記事では、既存LLMとSystem One Modelsを「対立」ではなく「役割分担」として整理している。

| 用途 | 適するモデル |
|---|---|
| 人間が介在する対話(チャットボット、コパイロット、コーディングエージェント) | 既存LLM(自由度が高い分、人間の監督が必要) |
| 検証可能な問題(数学証明、カーネル最適化) | 既存LLM(正しさを安く自動検証しながら生成・反復できる) |
| プロトタイプ・デモ | 既存LLM(文字列の柔軟性を活かした素早い試作) |
| **AI駆動ワークフロー/「賢いif文」**(分類・振り分け・スコアリング・抽出・分岐) | **Jev**(構造化出力が通常のソフトウェアに直接組み込める) |
| **ビッグデータのMap-Reduce処理**(大量データから特徴・洞察を抽出) | **Jev** |
| **リアルタイムアプリケーション**(UXがシビアな場面) | **Jev**(100ms級の速度) |
| **検証・ガードレール**(LLMの出力やプロンプトのジェイルブレイク検知等) | **Jev** |

## 提示されている実証データ(著者自身が誠実に限界も開示)

記事の特徴的な点として、**著者自身が「懐疑派を歓迎する」と明言し、主張ごとに"Nuance(留意点)"という注記を添えて、自ら弱点や測定条件の偏りを開示**している。

- **速度・コストの検証可能性:** 実測値は西海岸の自社ラップトップから計測したものであり、価格が長期的に持続可能かは今後の実績で証明する必要があると認めている
- **型エラーが起きないという主張:** 「反例が1つあれば簡単に反証できる主張だが、これは数学的に不可能な設計になっている」と説明
- **ワークフロー評価:** 正解データに対する分類精度ではなく、**GPT-6 Astra・Fable 5.1という最も賢く高価な外部モデルの平均予測を基準値**として比較する新しい評価方法を採用。この基準設定自体が**OpenAI・Anthropicのモデルに有利に働く可能性がある**ことも明記
- **公開されている「193.6倍速い、444.6倍安い」という数値**は、比較的条件の良いケースであり、実世界での効果はこれより控えめになりうるとも述べている

## デモ:DoomとWikiracing

- **Doom(ゲーム)**: テキストベースのゲーム状態表現に対してリアルタイムに反応するボットを構築。毎秒10クエリ(時間あたり約7ドル)というコストで動作
- **Wikiracing**: あるWikipediaページから別の指定ページへ、リンクだけを辿って到達するゲーム。数百〜数千のリンクから選択する高いカーディナリティ(選択肢の多さ)の判断において、**幻覚を起こさないことの複利的な効果**を示すデモとして紹介されている

## まとめ:この発表の位置づけ

- **「LLM vs Jev」という対立軸ではなく、「創造的・対話的タスクはLLM、高速・大量・構造化された意思決定はSystem One Model」という役割分担**を提案する内容
- AIエージェント運用の文脈で言うと、**「ガードレール」「検証」「振り分け」「大量データのバッチ処理」**のような、Prime自身が担っている実務的なタスクの一部を、将来的に専用モデルへオフロードできる可能性を示唆する発表といえる。例えば「ユーザーの入力が機密情報を含むか」「タスクの緊急度分類」といった、確率的だが構造化された判断は、まさにこの種のモデルの得意領域と重なる
- ただし早期アクセス段階の一企業による発表であり、著者自身も認める通り**第三者による長期的な検証はこれから**という段階。技術的に興味深いが、実運用への適用は今後の実績を見極める必要がある
